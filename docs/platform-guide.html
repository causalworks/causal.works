The Causal Platform, Explained

Two apps, one platform: what they share, who can do what, and how the pieces connect.

Causal is creating tooling for groups to launch and run their own platform cooperatives. Causal itself is an initiative, not a cooperative. The platform today is one account system with two apps: Cooperative, the sector-neutral operational core for nonprofits and coalitions in any field, and Agency, the first instance built on it, for grassroots advocacy and climate action. A person with Cooperative access moves between both with the same login. Underneath Cooperative, each organization's documents can live in its own Solid pod, under permissions the organization grants and can withdraw.

MapHow the pieces connect

AreasPlatform-level pieces, one at a time

Private tools, shared collaboration

  • Common needs framework. Each organization's management tools (budgeting, grants, accounting, compliance) are built around the operational needs nonprofits share, and every organization's instance is completely private to it. Access is strictly per organization.
  • Cooperative structure. Collaboration happens only in Workshop and the shared cooperative resources: the peer network, work library, and work pool.

Causal Platform Login

One account system and one session cookie for the whole platform. Login lands on the Cooperative workspace picker; an account without Cooperative access lands on Agency, and the sidebar links between the two. Login is by password or magic-link email, and an org invite (a hashed, expiring token) also starts a session.

Sessions last 30 minutes past the last activity by default. An organization admin can lengthen that (15 minutes to 8 hours) under Settings → Security. Separately, a fixed 15-minute unattended-browser auto-logout runs in both apps and is never relaxed. This login has no relationship to any Solid pod identity below.

Your Own Solid Identity prototype

A different kind of login from a Causal account. A person can log into their own Solid identity (a WebID) on Causal's Solid server, directly in the browser, using the Solid-OIDC standard. Causal's server never sees the password or tokens; they stay in the browser.

  • Logging in does nothing by itself. What that identity can read or write in an org's pod depends entirely on what an org admin has explicitly given that WebID.
  • It is not connected to Causal's roles, and it is reachable by anyone with a Causal login. Restricting it to a designated org admin, and deriving pod access from roles, are planned, not built.

Solid Pod Layer

Data sovereignty in practice: each organization's documents can live in its own Solid pod (Community Solid Server), outside Causal's database. Only the Document Vault is in the pod today. Budget and the rest of Cooperative stay in Postgres.

  • Per-document sync: nightly and on demand, with a confirmed-synced fact per document. The local copy is purged only after confirmation.
  • ACP permissions: scoped, time-limited or indefinite access on a document for a WebID, backed by real access-control policies in the pod.
  • Link sharing without a Solid identity: the recipient opens a Causal page and enters a one-time code emailed to the address the share was made for. The pod copy is private, and revoking or expiring the share stops access at once and deletes the copy. This proves control of a mailbox, not a Solid identity. Links made before September 24, 2026 stay open to anyone with the URL until revoked.
  • Access Groups: standing named groups (for example "Board") whose permissions cascade automatically through a transactional outbox.
  • Sync service, org-given: Causal's automated sync holds only a container-level permission on each org's own documents folder. It is revocable at any time, with no fallback credential.

Shared infrastructure

Node.js / Express 5 / PostgreSQL on one VPS under PM2. Isolation is enforced in the database: every organization's tables use row-level security, and program-linked tables add a program-level policy. Postmark sends all transactional email. Both apps share one stylesheet of design tokens and one PWA manifest.

Rough edges and what's next

Rough today

  • The Solid identity login is a prototype: it isn't restricted to org admins and isn't connected to roles.
  • Link recipients are verified by email, not by Solid identity. Shares made before September 24, 2026 stay open to anyone holding the URL until they are revoked.
  • No caching layer exists, so every read of a purged document fetches the pod fresh.
  • Encryption-at-rest for pod documents has a working prototype (AES-256-GCM, OpenBao-backed keys) but is a separate R&D track, not in the production pod.

Next

  • Pod sync beyond documents. Generated reports come first. Live data such as budgets would sync as periodic pod copies, with Causal's working copy staying in place.
  • Solid identity tied to roles. A person's pod access would follow from their role and programs, and link recipients could be verified by Solid identity, not only by email.
  • Finished roles. Per-action role checks for grants, personnel, fixed assets, fiscal-year locks, vendor compliance, and integrations.
  • Following across instances. Through Agency, individuals follow organizations on any Cooperative instance, chosen from a curated, human-approved list. Organizations already carry a stable external identifier for this.
  • New instances and governance. A platform agent recommends whether a proposed instance fits, and a human advisory group drawn from the adopters decides. How advisors are admitted and held accountable is not yet decided.
  • Shared Workshop copies. A Workshop stays in Causal's database as the one editable copy, and each participating organization's pod receives a one-way synced copy.

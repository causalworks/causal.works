The Agency App, Explained

A technical tour of Agency: where its data comes from, how following organizations shapes the feed, which external APIs it calls, where Gemini does the work, and the real filtering and ranking rules.

Agency is the first instance built on Causal's platform tooling, for grassroots advocacy and climate action. It connects individual decision-making to leverage points grounded in planetary boundaries science and Earth4All research. A person can sign petitions, attend events, volunteer, move money out of fossil-fuel banks, weigh in on regulatory comment periods, and see how their elected representatives connect to it all. Five sections: Home, Action (the action feed), Proxies (elected reps, advocates, financial tracking), Ledger, and Systems/Framework (planetary boundaries).

A person chooses which organizations to follow, and the feed pulls actions from those organizations. There is no single shared feed that looks the same to everyone.

AreasSection by section

Action: the unified feed

Every item is a "move" pulled from one actions feed and bucketed by type:

  • sign: petitions
  • attend: DB events + a live pull from Mobilize.us, defaulting to the user's saved ZIP within 25 miles; a search box lets the user query a different ZIP with a selectable radius (10/25/50/100mi)
  • volunteer: curated opportunities plus volunteer-type actions
  • vest: money moves (bank / invest / pension), shown separately from feed cards
  • comments: open regulatory comment periods and state permitting notices, sourced from the Federal Register API and EIP Oil & Gas Watch (see below)
  • anything else falls back to notify
Server filtering: GET /api/actions
Only shows actions from orgs the user follows, or user-sourced actions they already have. Excludes: already dismissed/completed, org subscription lapsed, out-of-region, needs manual review, decision window passed. Capped at 3 actions per org (window function) so no single org dominates.
Ranking
do-now first → real financial/personal stake → timing_confidence + boundary_urgency_score (combined) → newest first. Client re-sorts dated-soonest first, then groups attend → sign → volunteer → notify.

"Your rep is involved" badges are computed client-side by matching an action's target strings against the user's already-fetched representatives.

Comments tab: permitting and comment-period pipeline
Two scheduled jobs feed this tab and nothing else: a daily 04:00 UTC job pulls open public-comment periods from the Federal Register API, and a daily 05:00 UTC job (eip-oil-gas-watch-job.js) ingests EIP Oil & Gas Watch's state-level fossil-infrastructure permitting alerts (LNG terminals, compressor stations, gas storage) from a daily Excel export, since EIP has no public API. Both write into the same actions table; the Comments tab filters on source so these never leak into Sign/Attend.

Proxies: Elected · Advocates · Financial

"People and institutions acting on your behalf."

Elected: how a rep lookup actually happens
1. Address → Google Civic API divisionsByAddress → state + congressional district.
2. District matched against a locally-cached unitedstates/congress-legislators dataset (refreshed every 24h) for roster + committees.
3. Congress.gov API adds photo, party history, phone.
4. EU/UK users route through a separate matcher.
5. Re-runs automatically after onboarding or a ZIP/country change in Settings.

Rep-to-issue relevance uses a hardcoded table mapping 35 named committees and fiduciary boards to the five E4A turnarounds. This drives "your rep works on this" badges and the related-actions ranking.

Elections tab
Not live yet. The UI shows "Bills and Races: Coming soon" and links out to Ballotpedia's Sample Ballot Lookup. The FEC-backed endpoint (candidates filtered to incumbents or nonzero campaign receipts) is fully built server-side but nothing in the frontend calls it.

Advocates tab: orgs the user follows/gives to. Financial tab: read-only summary of where money exerts pressure, managed from Vest instead.

Fiduciary pledges (Financial tab)
A separate pledge system alongside the bank pledges below: users can pledge to press a pension/fund board (mapped via the same committee table above) to act by a date, with committed/acted/withdrawn status and reminder cards feeding back into Action.

Following organizations

A follow is a per-person choice. It decides which actions appear in Action, which organizations show as Advocates and in the Give list, and which forwarded emails are let through.

How an email becomes a card
Each person has a forwarding address for subscribing to organizations' email lists. Incoming mail is matched to an organization by sender domain (a domain belongs to one organization). Mail to a person's forwarding address goes through only when it comes from an organization they follow; otherwise it is archived. Mail that passes is classified by Gemini and becomes an entry in the actions feed.
Which organizations can be followed
The platform's curated list. A person can also keep a private list of organizations they give to; those are visible only to them and are not followed.

Ledger

The user's own giving and impact history, computed from their donation/contribution records.

Systems/Framework: planetary boundaries

The nine Stockholm Resilience Centre planetary boundaries (climate, biodiversity, freshwater, etc.), each carrying a status (safe/transgressed), a trend, and a transgression_severity score (0–3). Each maps to one or more of Causal's five E4A turnarounds, hand-maintained and refreshed annually after each Stockholm health check.

The one live computation
boundaryUrgencyScore = max severity across an action's tagged boundaries. Feeds straight into the Action feed ranking above.

AIAI / LLM usage: where and how

Everything AI-related runs on Google Gemini (gemini-2.5-flash) via the @google/generative-ai SDK or a raw REST call. Four use sites total.

Organization activity summaries gemini-2.5-flash

1–2 sentence "what has this org been doing" blurb, shown wherever an org is listed. Three-tier fallback, each its own prompt: summarize recent tracked actions → or summarize the org's earliest inbound outreach email → or fetch-and-summarize the org's own homepage text (plain HTTP fetch + tag strip, no headless browser).

Cached 14 days per org · live

Bank pressure-campaign lookup gemini-2.5-flash + Google Search grounding

GET /api/bank/pressure asks Gemini for 2–3 current (2025–2026) real campaigns or divestment actions targeting the specific bank the user named, with tools: [google_search] enabled so it can ground on live results. Expects JSON output.

Cached client-side per session · live

E4A turnaround / policy-parameter classifier gemini-2.5-flash, JSON mode

Reads inbound content (forwarded emails, submitted actions) and classifies it against the five E4A turnarounds and 19 underlying policy parameters. This is the pipeline that populates the turnaround_category tag used everywhere in Action and Proxies. Feed ranking and rep-relevance badges both depend on this having already run.

Live · upstream of most of the app

Congressional bill classification same approach, not wired up

Schema was designed for classifying bills into turnarounds with a rationale (bills_cache table, read by /api/reps/bills-rationale), but the table itself was dropped in a later migration and never rebuilt.

Dormant: endpoint currently errors

No AI is used for rep-matching, event lookup, or bank-alternative filtering. Those are deterministic API/data lookups, covered below.

LogicMoney-out logic

POST /api/bank/check: bank flag check
Plain substring match against a static, curated dataset of banks known for major fossil-fuel financing (sourced from public reporting, e.g. Banking on Climate Chaos). No API call.
GET /api/bank/alternatives-suggestions
Fully static/curated data, no geocoding API. Non-US users get fixed EU links. US users always see "Fossil Free Alliance"–certified banks unconditionally (so ZIP-less users still see something); everything else (mostly credit unions) is filtered to the user's state, extracted from their ZIP/address via a regex heuristic: abbreviation near ZIP, bare state abbreviation, full state-name match, or a Massachusetts ZIP-range fallback.
Bank pledges
Running pledge count per bank; the aggregate total is only displayed once at least 50 people have pledged against that bank, to avoid showing a discouragingly small number.

Rough edges and what's next

Rough today

  • Congressional bill classification (bills_cache) is dormant: the table was dropped in a later migration, so its endpoint currently errors.
  • Eventbrite and Action Network are stubbed as future event sources in local.js but need paid keys that aren't configured, so only Mobilize.us is live.
  • Every.org donation links are not active: no EVERYORG_PUBLIC_KEY is configured, so the endpoint 404s.
  • The EU/UK representative-matching path is separate code from the US path and less battle-tested.
  • Agency has no Solid pod integration. Personal data stays in Postgres.

Next

  • Following across instances. Through Agency, individuals follow organizations on any Cooperative instance, chosen from a curated, human-approved list.
  • Elections tab. It shows "Coming soon" and links out to Ballotpedia today. The FEC-backed candidate lookup is already built server-side and not yet used.
